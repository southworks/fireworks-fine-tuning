# Banking77 — intent classification case study

Banking77 is a public benchmark of 13,083 banking customer queries labelled with one of 77 intents
([PolyAI/banking77](https://huggingface.co/datasets/PolyAI/banking77), CC BY 4.0). It is the simpler,
fully-labelled companion to the Amazon purchasing case: one short input, one label out, an exact answer key.

The case is published in two forms:

1. **Frozen results (below):** the original experiment, which fine-tuned small Qwen models locally with
   Hugging Face Transformers + PEFT (LoRA with a classification head) and compared them with GPT models on
   Microsoft Foundry. These numbers are final and are not regenerated by this repository.
2. **Reproducible Fireworks path:** the same splits in chat format (`data/banking77/`) so the task can be
   fine-tuned and benchmarked on Fireworks as a *generative* classifier
   (`make train-model-banking77`, `make exec-benchmark-banking77`). Results from that path are a different experiment and will not match the
   frozen numbers exactly.

## Frozen results

Same 3,080-case test split for every row. Source files: `frozen-local/`.

| Model / mode | Accuracy | Macro-F1 | Tokens per request | vs. small model | Notes |
|---|---:|---:|---:|---:|---|
| **Qwen3.5-0.8B + LoRA, 2 epochs (local)** | **86.88%** | **86.89%** | ~12.6 input, 0 output | 1x | Classification head: output is always one of 77 labels |
| Qwen3-0.6B + LoRA, 2 epochs (local) | 85.06% | 85.09% | ~12.6 input, 0 output | 1x | |
| GPT-5.6 Luna, direct prompt with the 77 labels | 85.19% | 84.37% | 444 | 35x | Mean latency 1.78 s |
| GPT-5.6 Luna behind a Foundry agent | 84.71% | 83.99% | 4,903 | 389x | 96.7% of input tokens cached; 1 invalid label |
| GPT-4o behind a Foundry agent | 78.15% | 77.39% | 917 | 73x | 1 invalid label |
| Qwen3-0.6B, no fine-tuning | 15.16% | 13.90% | 640 | — | 589 invalid outputs |
| Qwen3.5-0.8B, no fine-tuning | 27.56% | 24.61% | 644 | — | |

Training cost of the best local model: 2 epochs, 2,252 optimizer steps, 4.13 h on an Apple-silicon laptop
(MPS), 1.6 GB of accelerator memory; batched inference ran at ~4.4 requests/s on the same laptop.

Reading:

- A 0.8B-parameter model fine-tuned on 9,002 examples matched or beat a frontier model on this narrow task
  (+1.69 pp accuracy, +2.52 pp macro-F1) while processing ~35x fewer tokens per request.
- Wrapping the large model in an agent did not improve quality and multiplied token volume.
- Without fine-tuning the small models are unusable (15–28% accuracy).
- Two epochs is the right budget for this setup: a third epoch degraded accuracy (38% / 32%), so the
  2-epoch checkpoints are the reported models.

## Reproducible path on Fireworks

Data (`data/banking77/`): `train.jsonl` 9,002 · `validation.jsonl` 1,001 · `test.jsonl` 3,080, chat format
(system instruction, customer query, intent label). Validation is a stratified 10% split of the original
training set (seed 42).

Historical Fireworks jobs on this data (records in `records/fireworks/`):

| Job | Output model | Base | Epochs | LR | LoRA rank | Batch | Duration | Est. cost |
|---|---|---|---:|---:|---:|---:|---:|---:|
| `jwbjh5ed` | `ft-qwen3-4b-banking` | Qwen3-4B | 3 | 1e-4 | 8 | 8 | 2 h 07 m | USD 0.77 |
| `n3gtjgd9` | `ft-qwen3-4b-banking-validation` | Qwen3-4B | 3 | 1e-4 | 8 | 8 | 2 h 25 m | USD 0.77 |

`configs/training/banking77.toml` uses the same settings with 2 epochs; the pipeline below trains and benchmarks it.

```bash
make upload-dataset-banking77               # banking77-train + banking77-eval
make train-model-banking77 DRY_RUN=1        # inspect the firectl request
make train-model-banking77                  # ~1.5 h; waits for the job
make deploy-base-model deploy-ft-model-banking77
make exec-benchmark-banking77 LIMIT=200     # base and GPT-5 get the 77-label list in the prompt;
                                            # the fine-tuned model gets its plain training instruction
make undeploy
```

Scoring (`scripts/benchmark/banking77.py score`) maps each answer to one of the 77 labels (exact, case-insensitive,
or a label embedded in a short sentence); anything else counts as an invalid output and as an error.
